환경 세팅 키트

사용설명서

이 폴더가 무엇이고, 무엇을 어떤 순서로 하며, 막혔을 때 어디를 보는지 전부 적었습니다.

빨리 시작만 하고 싶으시면 같은 폴더의 「이렇게_시작하세요.html」을 여십시오. 이 문서는 자세히 알고 싶을 때와 막혔을 때 찾아보는 것입니다.

01이 키트가 하는 일

이 컴퓨터를 「스킬·에이전트를 만들고 고칠 수 있는 상태」로 만듭니다.

세 가지를 합니다.

  • 잽니다 — 이 컴퓨터에 무엇이 있고 없는지 실제로 확인합니다. 짐작으로 적지 않습니다.
  • 안내서를 만듭니다 — 없는 것마다 이 컴퓨터에 맞는 설치 명령을 적어 줍니다.
  • 깔아 줍니다 — Claude가 그 안내서를 읽고, 하나씩 물어보며 설치를 이끕니다.
완료 기준이 둘입니다. 섞지 마십시오.
㉠ 기본 — 스킬을 하나 만들고, 고쳐서, 다시 써 보는 데 성공했다.
㉡ 연동까지 — 그 위에, 골라서 붙인 연동이 실제로 붙어 보인다.

도구가 다 깔렸다고 ㉠이 끝난 것이 아닙니다. 한 번 만들어 봐야 끝입니다.

02폴더 안에 무엇이 있나

폴더를 통째로 두십시오. 파일을 따로 꺼내면 서로를 찾지 못합니다.

파일무엇이고, 언제 보나
먼저_읽어보세요.txt맨 처음 여는 것. 어디서 시작하는지만 적혀 있습니다.
이렇게_시작하세요.html빠른 시작. 그림을 보며 네 걸음을 따라 합니다.
사용설명서.html지금 읽고 계신 문서. 자세히 알고 싶을 때와 막혔을 때.
이게_뭔가요.html파이썬·brew·node·git이 무엇인지 그림으로 설명합니다. 용어가 낯설 때.
직접_해야_하는_것.htmlClaude가 대신 못 하는 자리의 화면 그림. 그 자리가 왔을 때 해당 번호만 보십시오.
환경세팅설명글.html워크샵 설명글 21페이지. F를 누르면 전체화면이 됩니다.
아티팩트_설명.html아티팩트가 무엇인지.
Figma_MCP_설명.html · GA분석_세팅.html그 연동을 붙일 때만 봅니다.
맥/ · 윈도우/점검기가 들어 있습니다. 자기 운영체제 쪽만 쓰십시오.
.claude/숨김 폴더. 여기에 「환경세팅-도우미」 스킬이 있습니다. 이게 있어야 Claude가 도와줍니다.
.claude 폴더가 빠지면 아무것도 안 됩니다. 점(.)으로 시작해서 파인더에 안 보입니다. 압축 파일로 주고받을 때 빠지는 일이 있습니다 — /환경세팅-도우미가 목록에 안 뜨면 거의 이것 때문입니다. ⌘⇧.(커맨드-시프트-마침표)를 누르면 숨김 파일이 보입니다.

03네 걸음으로 끝냅니다

설치는 Claude가 대신 합니다. 사람이 할 일은 몇 가지뿐입니다.

1걸음 — Claude 앱을 열고 이 폴더를 엽니다

여기가 제일 헷갈리는 자리입니다. 셋을 정확히 고르셔야 합니다.

  • 왼쪽에서 Code를 누릅니다 (Chat 아닙니다)
  • 실행 위치는 Local을 고릅니다
    ⚠️ Cloud를 고르면 내 컴퓨터를 못 잽니다. 아무 의미가 없습니다.
  • 폴더는 이 폴더 전체를 고릅니다
    🚫 「맥」 폴더나 압축 파일을 고르면 안 됩니다.

「이 폴더를 믿어도 되나」·「명령을 실행해도 되나」를 물어봅니다. 오류가 아닙니다 — 허용하셔야 진행됩니다.

2걸음 — 입력창에 스킬 이름을 칩니다

/환경세팅-도우미

목록에 나오면 골라서 실행하십시오. 이게 보이면 첫 관문을 넘은 것입니다 — 로그인도 됐고, Local로 실행됐고, 폴더도 제대로 골랐다는 뜻입니다.

3걸음 — Claude가 이끕니다

  1. 먼저 잽니다. 점검기를 돌려 무엇이 없는지 확인합니다.
  2. 무엇을 할지 먼저 고르게 합니다. 기본만 할지, 연동을 붙일지.
    순서가 중요합니다 — 무엇이 필요한지는 무엇을 붙일지 정한 뒤에 결정됩니다. 피그마를 고르면 그때 Node.js가 필요해지는 식입니다. 안 쓸 것은 안 깝니다.
  3. 하나씩, 물어보고 깝니다. 남의 컴퓨터니까요.
  4. 깔 때마다 정말 깔렸나 다시 재서 확인합니다. 「명령이 오류 없이 끝났다」를 「깔렸다」로 읽지 않습니다.
  5. 안 깔리면 거기서 멈춥니다. 앞의 것이 뒤의 것을 깔아 주는 도구라, 앞이 없으면 뒤는 어차피 안 됩니다.

4걸음 — 진짜 되는지 함께 시험합니다

도구가 다 깔려 있어도 스킬을 만들고 고치지 못하면 끝난 게 아닙니다. 그래서 한 번 해 봅니다.

  1. 연습용 스킬을 하나 만듭니다
  2. Claude Code를 닫고 다시 엽니다 — 그러지 않으면 새 스킬이 안 보입니다
  3. 입력창에 /연습을 쳐서 목록에 나오는지 봅니다
  4. 설명을 한 줄 고치고, 다시 열어 바뀐 것이 보이는지 봅니다

되면 끝입니다. 이제 「이런 일은 이렇게 해 줘」를 적어 두면 다음부터는 그 이름만 부르면 됩니다. 그게 스킬입니다.

04점검기가 재는 것

아무것도 설치하지 않습니다. 재기만 하고 안내서를 만듭니다.

점검기는 맥/맥에서_두번누르기.command(윈도우는 윈도우/윈도우에서_두번누르기.bat)를 두 번 눌러도 돌고, 도우미가 알아서 돌리기도 합니다. 결과는 같은 폴더에 환경점검_결과.html로 생기고 저절로 열립니다.

갈래무엇없으면
반드시 필요한 것 Xcode 명령줄 도구 · git
(애플 실리콘 맥은 Homebrew도)		 여기서 막히면 시작을 못 합니다
골라 쓰는 것 Node.js · npx · Python 3 · uv · bun 붙일 연동이 요구할 때만 깝니다. 전부 깔 필요 없습니다
연동을 붙일 때만 claude 터미널 명령 스킬을 만들고 고치는 데는 없어도 됩니다 — 데스크탑 앱으로 됩니다
있으면 좋은 GitHub CLI · VS Code 없어도 시작은 됩니다. 나중에 보태도 괜찮습니다
연동(MCP) Claude Design · 바이널씨 볼트 · 피그마 · 구글 애널리틱스 필요한 것만 고르십시오
점검기는 값을 읽지 않습니다. 연동이 등록돼 있는지는 이름만 봅니다. 토큰·비밀번호·계정 값은 열어 보지 않습니다.
그래서 「설정에 이름 있음」이 실제로 붙었다는 뜻은 아닙니다 — 인증이 만료됐거나 서버가 죽었을 수 있습니다. Claude Code에서 /mcp로 확인하십시오.

05설치 — 맡길까, 직접 할까

두 길이 있습니다. 어느 쪽이든 무엇이 도는지는 안내서에 그대로 적혀 있습니다.

①Claude에게 맡기기

폴더를 Claude 앱에서 열고 /환경세팅-도우미를 부르면, 안내서에 적힌 명령을 하나씩 물어보며 대신 돌려 줍니다. 무엇을 왜 하는지 매번 알려 드리고, 깐 뒤에는 다시 재서 확인합니다.

명령을 실행할 때마다 Claude Code가 허용할지 물어봅니다 — 보고 나서 허용하시면 됩니다.

②직접 하기

안내서의 명령을 복사해 터미널에 붙여 넣습니다. 회사 방침상 명령 실행을 맡길 수 없을 때는 이쪽입니다.

터미널을 여는 법은 「직접_해야_하는_것.html」 1번에 그림으로 있습니다.

어느 쪽이든 사람이 직접 해야 하는 자리가 있습니다. 비밀번호를 묻는 설치와, 창이 떠서 눌러야 하는 것과, 브라우저 로그인입니다. 06번을 보십시오.

Claude는 왜 매번 물어보나

남의 컴퓨터이기 때문입니다. 그리고 안내서에 적힌 명령만 씁니다 — 「보통 이렇게 깐다」로 명령을 지어내지 않습니다. 판이 바뀌면 그 기억이 틀리고, 틀린 명령은 이상한 것을 깔거나 아무것도 안 깔고 헤매게 만듭니다. 안내서는 이 컴퓨터를 실제로 재서 만든 것이라, Claude의 기억보다 그것이 정본입니다.

06사람이 직접 해야 하는 자리

네 군데입니다. 그 자리가 오면 Claude가 「직접_해야_하는_것」의 몇 번인지 알려 줍니다.

언제왜 Claude가 못 하나
Xcode 명령줄 도구 설치창이 떠서 사람이 [설치]를 눌러야 합니다
Homebrew 설치
(애플 실리콘 맥만)		관리자 비밀번호를 물어봅니다
구글 · GitHub 로그인브라우저에서 계정을 골라야 합니다
피그마 플러그인 불러오기피그마 앱 안에서 골라야 합니다
비밀번호·인증번호·복구 코드는 Claude에게 알려 주지 마십시오. 묻지도 않습니다. 비밀번호를 넣는 자리가 나오면 그건 사람이 자기 손으로 넣는 자리입니다. GitHub 복구 코드도 마찬가지입니다.
남의 설정 파일을 복사해 쓰지 마십시오. 연동 설정 파일에는 그 사람의 접근 열쇠가 들어 있습니다. 복사해 쓰면 남의 권한으로 접속하는 것이 되고, 그 사람이 열쇠를 바꾸는 순간 멈춥니다. 연동은 반드시 각자 자기 계정으로 등록하십시오.

07인텔 맥이면 달라지는 것

Homebrew를 쓰지 않습니다. 점검기가 알아서 갈라 주니 따로 하실 일은 없습니다.

2026년 9월, Homebrew가 인텔 맥 지원을 3등급으로 내렸습니다. 미리 만들어 둔 꾸러미를 더 이상 갱신하지 않아서, brew install이 몇 시간씩 컴파일하거나 그냥 실패합니다 (no bottle available!).

그래서 인텔 맥에서는 필요한 것을 웹사이트에서 직접 받는 길로 안내합니다. 결과 안내서 머리에 「이 컴퓨터는 인텔 맥입니다」가 붙으면 그 길로 가고 있는 것입니다.

무엇인텔 맥에서는비밀번호
claude 터미널 명령claude.ai/install.sh안 묻습니다
Node.jsnodejs.org 압축본을 홈 폴더에 풉니다안 묻습니다
uvastral.sh/uv/install.sh안 묻습니다
VS Code홈 폴더 안 「응용 프로그램」에 풉니다안 묻습니다
GitHub CLI공식 설치본(.pkg)묻습니다 — 직접 하십시오
Python 3Xcode 명령줄 도구에 이미 들어 있습니다—
bun🚫 권하지 않습니다—
인텔 맥에서 bun을 권하지 않는 까닭 — 구형 인텔 CPU(AVX2 미지원)에서 Illegal instruction으로 죽는 사례가 보고돼 있습니다. bun은 피그마 중계 방식에만 쓰입니다. 피그마를 쓰셔야 하면 담당자에게 공식 연동 쪽을 물어보십시오.

🙋 Homebrew가 이미 깔려 있고 잘 돌아간다면 지우실 필요 없습니다. 그냥 두시면 됩니다.

08막혔을 때 — 증상별

증상을 찾아 그 칸만 보십시오. 막히면 다음 단계로 넘어가지 마십시오.

입력창에 /환경세팅-도우미가 안 뜹니다

거의 항상 폴더를 잘못 고른 것입니다. 「맥」 폴더나 압축 파일이 아니라 이 폴더 전체를 골라야 합니다.

그래도 안 보이면 압축을 풀 때 점(.)으로 시작하는 숨은 폴더가 빠진 것입니다. ⌘⇧.로 숨김 파일을 켜고 .claude가 있는지 확인하십시오. 없으면 폴더를 다시 받으십시오.

맥이 「확인되지 않은 개발자」라며 안 열립니다

그 파일을 오른쪽 클릭 → [열기], 다시 [열기]를 누르십시오. 인터넷에서 받은 파일은 맥이 한 번 막습니다. 한 번만 그렇게 하면 그다음부터는 그냥 열립니다.

깔았는데 command not found라고 나옵니다

터미널 창을 닫고 새로 여십시오. 터미널은 열릴 때 한 번만 둘러봅니다 — 새로 깐 것은 새 창에서야 보입니다. 연동을 등록했을 때도 마찬가지로 Claude Code를 닫고 다시 열어야 합니다.

brew install이 끝나지 않습니다 / no bottle available

인텔 맥입니다. 07번을 보십시오. 기다려도 풀리지 않습니다 — 멈추고(Control + C) 직접 받는 길로 가십시오.

연동을 등록했는데 /mcp에 안 보입니다

Claude Code를 완전히 닫고 다시 여십시오. 세션 중에 등록한 연동은 다시 열어야 보입니다.

GA를 붙였는데 수치가 안 보입니다

거의 항상 어느 계정으로 로그인했나의 문제입니다. 설치를 잘못한 게 아닙니다. 개인 구글 계정으로 로그인했으면 아무것도 안 보입니다 — 그 계정에는 볼 권한이 없습니다. 담당자에게 받은 계정인지 확인하고, 로그인만 다시 하십시오. 🚫 다시 깔지는 마십시오.

피그마가 중간에 막힙니다

호출 한도일 수 있습니다. 피그마 연동은 월 단위 한도가 꽤 빡빡하고, 다 쓰면 그리기는 물론 읽기까지 막힙니다. 월 단위라 기다려도 안 풀립니다.

그 밖에 — 무엇이 문제인지 모르겠습니다

설명하려 애쓰지 마시고 화면을 그대로 보여 주십시오.

  1. 맥에서 shift + control + command + 4를 함께 누릅니다
  2. 커서가 십자로 바뀌면 오류 난 자리나 멈춘 화면을 드래그해 감쌉니다
  3. Claude Code 창에 그대로 붙여넣습니다 (command + V)

control을 함께 누르는 것이 핵심입니다 — 파일로 저장되지 않고 복사만 됩니다. 무엇을 하려다 멈췄는지 한 줄만 함께 적어 주시면 더 좋습니다.

09자주 묻는 것

터미널을 꼭 써야 하나요?

거의 안 쓰셔도 됩니다. 스킬을 만들고 고치는 데는 데스크탑 앱만으로 충분합니다. 터미널은 도구를 깔 때만 잠깐 나오고, 그것도 Claude에게 맡기실 수 있습니다.

전부 다 깔아야 하나요?

아닙니다. 「반드시 필요한 것」만 있으면 시작됩니다. 나머지는 붙일 연동을 고른 뒤 그것이 요구하는 것만 깝니다. 안 쓸 연동은 안 붙이는 것이 맞습니다.

점검을 여러 번 돌려도 되나요?

됩니다. 오히려 무언가를 깔 때마다 다시 돌리십시오. 아무것도 설치하지 않고 재기만 하므로 몇 번을 돌려도 안전합니다.

회사 방침상 명령 실행을 맡길 수 없습니다

점검기를 두 번 눌러 직접 돌리십시오 — 맥은 맥/맥에서_두번누르기.command, 윈도우는 윈도우/윈도우에서_두번누르기.bat입니다. 재기만 하고, 없는 것마다 붙여 넣을 명령이 나옵니다.

Claude 데스크탑 앱과 터미널 claude는 뭐가 다른가요?

같은 Claude Code입니다. 들어가는 문만 다릅니다. 스킬을 만들고 고치는 데는 터미널 명령이 필요 없습니다. 연동을 명령으로 등록할 때만 씁니다.

이 폴더를 옮겨도 되나요?

됩니다. 폴더째로만 옮기시면 자리는 어디든 상관없습니다 — 파일들이 자기가 있는 자리를 스스로 찾습니다.

10지켜 주실 것

  • 비밀번호·인증번호·복구 코드는 Claude에게 알려 주지 마십시오. 묻지도 않습니다.
  • 남의 설정 파일을 복사해 쓰지 마십시오. 연동은 각자 자기 계정으로 등록합니다.
  • 무언가를 깐 뒤에는 창을 새로 여십시오. 터미널도, Claude Code도.
  • 막히면 그 자리에서 멈추고 물어보십시오. 다음 칸으로 넘어가지 마십시오 — 앞의 것이 뒤의 것을 깔아 주는 도구라, 앞이 없으면 뒤는 어차피 안 됩니다.
  • 바깥에서 받은 프로그램은 회사 방침을 먼저 확인하십시오. 피그마 중계 방식이 여기 해당합니다.
